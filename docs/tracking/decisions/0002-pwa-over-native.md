# 0002 — 네이티브 앱이 아니라 PWA + 웹푸시

**맥락**: "앱 스케쥴 창"과 "알람"이라는 요구를 만족시킬 방법으로 네이티브 모바일 앱(iOS/
Android), 설치형 웹앱(PWA), 카카오톡/텔레그램 봇 + 웹페이지 세 가지를 검토했다.

**결정**: PWA(홈 화면에 설치하는 웹앱) + 표준 웹푸시(Push API/VAPID)로 구현한다.

**대안과 기각 사유**: 네이티브 앱은 푸시 안정성이 가장 높지만 스토어 배포/설치 절차가 개인
규모 프로젝트에 비해 부담이 크다는 이유로 기각. 봇 + 웹페이지는 개발이 가장 간단하지만
"앱 스케쥴 화면"이라는 요구와 거리가 있다는 이유로 기각. PWA는 개발/배포 부담이 낮으면서도
두 요구를 모두 만족한다고 판단해 채택했다.

**결과**: iOS는 16.4 이상에서 PWA를 홈 화면에 추가해야만 웹푸시가 동작하는 플랫폼 제약이
있다 — 사용자가 이 제약을 인지한 상태로 채택을 확정했다. 서비스워커(`public/sw.js`)와
`manifest.json`이 필요해졌고, 웹푸시 발송을 위해 VAPID 키 쌍과 `web-push` 패키지가
추가됐다.
