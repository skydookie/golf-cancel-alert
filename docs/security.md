# security.md — 보안 정책

## 인증 흐름 (App User)

1. `/api/auth/signup` — 초대코드(`INVITE_CODE` 환경변수와 정확히 일치해야 함) 검증 → 실패 시
   403, 이메일 중복 검사는 실행되지 않음. 초대코드 통과 후 이메일 중복 검사 → 실패 시 409.
   비밀번호는 bcrypt(round 12)로 해시해서 저장, 세션 쿠키 발급.
2. `/api/auth/login` — 이메일로 User 조회 → 없거나 비밀번호 불일치 시 **동일하게** 401(둘의
   메시지·상태코드를 구분하지 않음 — 존재하는 이메일 목록을 추측당하지 않기 위함).
3. 세션은 `session` 쿠키(HttpOnly, `SameSite=Lax`, 프로덕션에서 `Secure`)에 담긴 JWT(HS256,
   `SESSION_SECRET`로 서명, 30일 만료)다. 만료되거나 서명이 위조된 토큰은 `verifySessionToken`이
   예외 없이 `null`을 반환 — 그 요청은 비로그인 취급.
4. 모든 인증 필요 API는 `getUserIdFromRequest`로 세션 쿠키를 검증해 `userId`를 얻는다. 쿠키가
   없거나 무효면 401.
5. 미들웨어(`src/middleware.ts`)가 `/schedule`, `/settings` 접근 시 세션 쿠키의 **서명 유효성만**
   검사해 리다이렉트한다(DB 조회는 하지 않음 — Edge 런타임 제약). 실제 데이터 접근 권한은 각 API
   라우트가 다시 검증한다(미들웨어는 UX용 리다이렉트일 뿐, 권한의 최종 방어선이 아니다).

## 인가 모델

| 주체 | 대상 | 허용 | 불허 |
|---|---|---|---|
| 로그인한 User | 자신의 WatchCondition / FacilityCredential / NotificationLog / PushSubscription | 조회·생성·수정·삭제 | — |
| 로그인한 User | 다른 User의 위 리소스 | — | 전부 불허. 다른 User 소유 리소스에 대한 요청은 404(권한 없음을 알리지 않고 "없음"으로 응답) |
| 비로그인 요청 | 위 모든 리소스 | — | 전부 401 |
| 외부 스케줄러(GitHub Actions) | `/api/cron/scan` | `Authorization: Bearer <CRON_SECRET>` 일치 시에만 호출 가능 | 불일치/누락 시 401, 감시 사이클 실행 안 됨 |
| 가입 희망자 | `/api/auth/signup` | `INVITE_CODE`와 정확히 일치하는 초대코드 제출 시에만 계정 생성 | 불일치/누락 시 403, 계정 생성 안 됨 |

## 자격증명 관리

| 자격증명 | 저장 방식 | 생성 | 갱신 | 폐기 |
|---|---|---|---|---|
| App User 비밀번호 | bcrypt 단방향 해시 — **복원 불가능**, 로그인 시 비교만 | 가입 시 | 없음(변경 API 미구현 — `docs/tracking/status.md` 참고) | User 탈퇴 시 레코드째 삭제 |
| FacilityCredential 아이디/비밀번호 | AES-256-GCM 가역 암호화(`CREDENTIAL_ENCRYPTION_KEY`, 32바이트) — 감시 사이클이 복호화해서 실제 로그인에 사용 | 등록 시 | `PATCH`로 아이디/비밀번호 갱신 시 재암호화 + 상태 `ACTIVE`로 복귀 | 등록 삭제 또는 User 탈퇴 시 레코드째 삭제 |
| 세션 토큰(JWT) | 서버는 저장하지 않음(무상태) — 클라이언트 쿠키에만 존재 | 로그인/가입 성공 시 발급 | 재로그인 시 새로 발급 | 로그아웃 시 쿠키 제거, 또는 30일 후 자연 만료 |
| 웹푸시 구독 키 | 평문 저장(공개키 성격의 값 — 이것만으로 알림을 보낼 수 있을 뿐 계정 탈취에 쓰이지 않음) | 클라이언트가 구독 등록 시 | 없음(구독이 바뀌면 endpoint가 바뀌어 새 레코드) | 410/404 응답 시 자동 삭제, 또는 User 탈퇴 시 연쇄 삭제 |

## 민감정보 취급

- 골프장 계정 비밀번호와 App User 비밀번호는 어떤 API 응답에도 포함되지 않는다(`toPublicShape`
  류의 변환 함수가 항상 상태·타임스탬프만 반환하고 자격증명 필드 자체를 걸러낸다).
- 암호화/해시 실패(환경변수 누락 등)는 예외를 던져 요청을 실패시킨다 — 평문으로 대체 저장하는
  폴백 경로는 없다.
- 감시 사이클이 복호화한 평문 아이디/비밀번호는 어댑터의 `login()` 호출 인자로만 쓰이고, 로그나
  DB에 다시 쓰이지 않는다.

## 감사(audit) 대상

- 로그인 실패로 인한 자격증명 일시중지 이벤트는 `FacilityCredential.lastError` 필드에 남는다(
  타임스탬프는 `updatedAt`).
- 발송된 알림은 전부 `NotificationLog`에 영구 기록된다(어떤 User에게, 어떤 슬롯에 대해, 언제).
- 그 외 별도의 감사 로그 저장소는 없다 — 개인 규모 서비스로, 침해 대응용 감사 체계는 범위 밖이다.

## 접근 제어(가입 게이트)의 이유

무료 티어 클라우드 자원(DB·호스팅·스캔 주기)을 초대받지 않은 사람과 나눠 쓰지 않기 위해
초대코드를 요구한다. 초대코드는 현재 앱 전체에 **하나의 공용 값**(`INVITE_CODE` 환경변수)이다 —
누구에게 발급됐는지 개별 추적하지 않는다(그런 추적이 필요해지면 코드를 여러 개로 분리해야 하며,
이는 계획된 확장이 아니라 별도 결정이 필요한 변경이다).
